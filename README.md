# Have Come, Have Go

> 中文名：**有来有往**  
> 当前状态：🚧 早期交互原型，持续开发中

**爱可以感性，钱最好清醒。**

“有来有往”不是情侣共同账本，也不是为了鼓励人在关系里斤斤计较。它是一款面向个人的关系支出记录与自我觉察工具：帮助人留下事实、看见长期的付出，并在真正重要的钱上及时把话说清楚。

这个项目来自一名中国律师对真实关系纠纷的观察：很多争议并不是一开始就无法解决，而是在付款、转账和承诺发生时，没有人把款项性质、双方理解和相关材料认真留下来。等到关系变化，事实已经被情绪和时间冲淡。

我们想尝试做一件更温和的事：

> 平时帮助用户尊重自己的付出；需要的时候，帮助用户把事实整理清楚。

## 它关心的不是“钱花到哪里”

普通记账工具通常回答：

> 这笔钱属于餐饮、旅行、购物还是转账？

“有来有往”还会继续追问：

> 这笔钱发生在什么关系中？是谁支付的？有没有附言和上下文？是否期待返还？现在需要留下哪些事实？

产品不会仅凭关系名称或单方记录自动下法律结论。朋友、约会、相亲、暧昧、恋人和夫妻，只是理解事实的背景，不是“借款”“赠与”或“共同消费”的自动答案。

## 当前可以体验的功能

### 1. 个人关系记录

- 新建并切换朋友、约会、相亲、暧昧、恋人、夫妻等关系；
- 使用文字或截图记录金额、时间、付款方、类目、转账附言和自己的一句话；
- 截图只处理用户主动选择的一张图片，并在本地压缩保存；
- 每段关系独立统计，记录默认只属于用户自己。

### 2. 关系支出觉察

- 查看本月由自己承担的金额；
- 发现连续多次单方面付款；
- 设置月度支出、单笔大额和法律关注金额；
- 不要求记录每一笔小钱，主要提醒大额给付、长期单方面付款和以后可能需要核对的事实。

### 3. “理想回应”视角

用户可以在“我的记录”和“理想中的对方”之间切换。

这个视角不是展示给收款方，也不推断现实中的对方真正怎么想。它只是让付款方听见一种理想的回应：

> “今天又是他付钱，我应该认真记得。”  
> “工作都不容易，下次不能再让他一个人承担。”

它尝试呈现的，是人在付出后可能期待、却没有被说出口的看见与尊重。

### 4. 该说清的钱

- 将需要进一步确认的转账集中展示；
- 提醒检查付款截图、转账附言、前后对话、通话录音、短信、邮件、借条和后续还款；
- 生成借款事实确认或款项性质确认的沟通草稿；
- 金额达到关注线时生成本地事项摘要；
- 清楚区分单方记录、对方确认、可靠电子签署和律师意见。

### 5. 法律小课

- 初期展示中国法下与借款、赠与、转账凭证和电子证据有关的基础内容；
- 链接至最高人民法院官方原文；
- 只做一般普法，不根据用户的单方记录自动认定款项性质；
- 英文界面用于涉及中国的跨国婚姻或涉外关系，法律内容仍以中国法为主。

### 6. 本地隐私机制

- 当前原型不连接业务服务器；
- 没有账户同步、微信钱包读取、律师共享或后台上传；
- 隐私中心会显示本地关系、记录、截图数量和大致空间占用；
- 用户可以主动导出完整本地备份，或清除全部个人数据；
- 达到提醒金额不会自动联系律师，也不会发送任何记录。

更完整的产品边界见 [隐私机制草案](./隐私机制草案.md)。

## 微信付款同步说明

目前的“微信付款同步”仅是交互概念演示，使用示例数据，不连接真实微信账户，也不读取用户的钱包或聊天记录。

普通授权并不意味着产品可以取得用户的全部个人交易流水。未来会继续研究以下更现实的路径：

- 用户主动选择付款截图；
- 本地 OCR 后由用户核对字段；
- 用户主动导入账单文件；
- 在平台明确允许的支付场景中生成待完善记录。

## 提醒功能说明

当前可以体验应用内提醒和浏览器通知。浏览器通知需要用户主动授权，页面关闭后不保证后台送达。

正式小程序若接入微信订阅消息或服务号，必须再次取得用户订阅，并遵守平台模板和发送场景限制。提醒服务不应读取或保存用户的完整关系记录。

## 目前还没有实现

- 真实微信付款记录同步；
- OCR 自动识别并核验付款信息；
- 服务器、账户及跨设备同步；
- 正式微信订阅消息或服务号提醒；
- 双方身份核验和可靠电子签署；
- 真实律师账户、自动咨询或材料上传；
- 可作为正式证据保险箱的加密、可信时间戳和完整性验证。

## 在 Windows 上体验

无需安装依赖：

1. 下载或克隆本仓库；
2. 双击 `启动体验.cmd`；
3. 浏览器会自动打开原型。

也可以直接打开 `index.html`。建议使用 Edge 或 Chrome。

当前数据保存在打开页面的浏览器中。测试前请记住：清理浏览器数据可能导致记录消失，不要将本原型作为重要材料的唯一备份。

## 接下来想探索什么

项目仍处于非常早期的产品验证阶段，目前更关心问题是否真实，而不是快速堆叠功能：

- 人们是否愿意记录较大或长期单方面的关系支出？
- 怎样提醒，既能让人看见自己，又不制造对立和焦虑？
- 哪些款项值得邀请对方确认？
- 如何在“完全本地保存”和“双方协作确认”之间建立清楚边界？
- 怎样生成一份对 AI 和律师都真正有用的事实材料，而不是替用户草率定性？
- 微信小程序、本地单机 App 和律师服务入口，分别应该承担什么角色？

## 重要说明

本项目当前仅为产品交互原型，不提供法律服务，页面中的分类、提示、文书和普法内容不构成针对任何具体事项的法律意见。涉及真实争议时，应结合原始材料和完整事实向具备相应资格的专业人士咨询。

本仓库目前尚未指定开源许可证。代码公开用于产品交流和测试反馈，不当然表示授权复制、发布或商业使用。
