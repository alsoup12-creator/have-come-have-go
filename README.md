# Have Come, Have Go

> 中文名：**有来有往**  
> 当前状态：🚧 早期交互原型，持续开发中

**爱可以感性，钱最好清醒。**

“有来有往”不是情侣共同账本，也不是为了鼓励人在关系里斤斤计较。它是一款面向个人的关系支出记录与自我觉察工具：帮助人留下事实、看见长期的付出，并在真正重要的钱上及时把话说清楚。

这个项目来自一名中国律师对真实关系纠纷的观察：很多争议并不是一开始就无法解决，而是在付款、转账和承诺发生时，没有人把款项性质、双方理解和相关材料认真留下来。等到关系变化，事实已经被情绪和时间冲淡。

我们想尝试做一件更温和的事：

> 平时帮助用户尊重自己的付出；需要的时候，帮助用户把事实整理清楚。

## 它关心的不是“钱花到哪里”

普通记账工具通常回答：

> 这笔钱属于餐饮、旅行、购物还是转账？

“有来有往”还会继续追问：

> 这笔钱发生在什么关系中？是谁支付的？有没有附言和上下文？是否期待返还？现在需要留下哪些事实？

产品不会仅凭关系名称或单方记录自动下法律结论。朋友、约会、相亲、暧昧、恋人和夫妻，只是理解事实的背景，不是“借款”“赠与”或“共同消费”的自动答案。

## 当前可以体验的功能

### 1. 个人关系记录

- 新建并切换朋友、约会、相亲、暧昧、恋人、夫妻等关系；
- “今天”和“记录”始终聚焦当前选中的一段关系，通过顶部关系条切换；
- “说清”和“我的”铺开展示全部关系，默认汇总所有关系；点击某一关系后，只显示该关系的金额、记录和提醒；关系卡和“我的”统计同时呈现本月与本年口径；
- 使用文字、截图、拍摄小票或礼物记录金额、时间、类目、转账附言和自己的一句话；
- 截图和小票只处理用户主动选择的图片，并在本地压缩保存；
- 每笔新记录都代表用户自己的支出，不再建立“对方付款”流水；
- 新增记录时必须明确选择所属关系，每段关系独立统计。

### 2. 关系支出觉察

- 查看本月由自己承担的金额；
- 发现短期内多次支出、连续送礼或大额付款；
- 朋友、约会、相亲和暧昧关系出现连续送礼或大额付款时，提醒用户重新观察关系进展、对方是否有相应付出，以及自己实际得到了什么；
- 由用户自行设置月度累计、年度累计、单笔大额和法律关注提醒线；填写 0 可以关闭对应金额提醒；
- 不要求记录每一笔小钱，主要提醒大额给付、长期单方面付款和以后可能需要核对的事实。

### 3. “理想回应”视角

用户在选中一段具体关系后，可以在“我的记录”和“理想回应”之间切换。不同关系使用不同语气：朋友关系保持中性，约会、相亲和暧昧关系强调节奏与边界，恋人和夫妻则分别体现感情回应与共同承担。

这个视角不是展示给收款方，也不推断现实中的对方真正怎么想。它只是让付款方听见一种理想的回应：

> “今天又是他付钱，我应该认真记得。”  
> “工作都不容易，下次不能再让他一个人承担。”

在朋友关系中，文案会更像：

> “好朋友会默默记下。”
>
> “真正的朋友不会把你的照顾当作理所当然。”

它尝试呈现的，是人在付出后可能期待、却没有被说出口的看见与尊重。

### 4. 该说清的钱

- 按付款月份和类目归类展示用户自己的记录，支持逐笔选择、按筛选范围全选和清空；勾选时保留当前浏览位置，月份与类目标题明确区分“当前范围”和“已选择”口径；
- 提醒检查付款截图、转账附言、前后对话、通话录音、短信、邮件、借条和后续还款；
- “直面模式”把同一段关系中的选中款项生成给对方核对的确认内容，正式小程序中可由用户主动转发；
- “开不了口模式”把选中记录、证据情况和用户留言整理为律所公众号后台咨询包，提交前完整预览；
- 清楚区分单方记录、对方确认、可靠电子签署和律师意见。

### 5. 法律小课

- 初期展示中国法下与借款、赠与、转账凭证和电子证据有关的基础内容；
- 链接至最高人民法院官方原文；
- 只做一般普法，不根据用户的单方记录自动认定款项性质；
- 英文界面用于涉及中国的跨国婚姻或涉外关系，法律内容仍以中国法为主。

### 6. 本地隐私机制

- 当前原型不连接业务服务器；
- 没有账户同步、微信钱包读取、律师共享或后台上传；
- 隐私中心会显示本地关系、记录、截图数量和大致空间占用；
- 用户可以主动导出完整本地备份，或清除全部个人数据；
- 达到提醒金额不会自动联系律师，也不会发送任何记录。
- 当前网页原型中的微信转发和律所后台提交都只展示交互预览，不创建真实链接，也不发送数据。

更完整的产品边界见 [隐私机制草案](./隐私机制草案.md)。

## 为什么不做微信付款流水同步

产品不会读取或同步用户的完整微信支付流水。多数个人消费与当前关系无关，整批导入会迫使产品长期清洗、筛选和推测交易用途，也会扩大不必要的数据处理范围。这与“用户主动留下重要事实”的定位不一致。

当前只保留四种主动记录方式：

- 文字记录；
- 付款或聊天截图；
- 拍摄或选择小票；
- 备注礼物名称和金额。

## 聊天材料怎么保存

微信小程序可以调用 [`wx.chooseMessageFile`](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.chooseMessageFile.html)，让用户主动从客户端会话中选择图片或文件，并可一次选择多项。但这只是选择会话里已有的图片或文件，不是读取微信聊天历史；普通文字消息不能直接批量导入成结构化对话。

因此，初期更适合采用截图或长截图。正式小程序可以进一步支持多张聊天截图连续选择、手动排序和完整预览，但不应宣称“导入聊天记录”，也不应在用户不知情时读取聊天内容。保留材料时，尽量保存带有前后文、时间和双方身份线索的完整截图，避免只截取孤立的一句话。

## 提醒功能说明

当前可以体验应用内提醒和浏览器通知。浏览器通知需要用户主动授权，页面关闭后不保证后台送达。

正式小程序若接入微信订阅消息或服务号，必须再次取得用户订阅，并遵守平台模板和发送场景限制。提醒服务不应读取或保存用户的完整关系记录。

## 目前还没有实现

- 聊天截图多选、顺序整理及长图预览；
- OCR 自动识别并核验付款信息；
- 服务器、账户及跨设备同步；
- 正式微信订阅消息或服务号提醒；
- 双方身份核验和可靠电子签署；
- 真实律师账户、自动咨询或材料上传；
- 可作为正式证据保险箱的加密、可信时间戳和完整性验证。

## 在 Windows 上体验

无需安装依赖：

1. 下载或克隆本仓库；
2. 双击 `启动体验.cmd`；
3. 浏览器会自动打开原型。

也可以直接打开 `index.html`。建议使用 Edge 或 Chrome。

当前数据保存在打开页面的浏览器中。测试前请记住：清理浏览器数据可能导致记录消失，不要将本原型作为重要材料的唯一备份。

## 接下来想探索什么

项目仍处于非常早期的产品验证阶段，目前更关心问题是否真实，而不是快速堆叠功能：

- 人们是否愿意记录较大或长期单方面的关系支出？
- 怎样提醒，既能让人看见自己，又不制造对立和焦虑？
- 哪些款项值得邀请对方确认？
- 如何在“完全本地保存”和“双方协作确认”之间建立清楚边界？
- 怎样生成一份对 AI 和律师都真正有用的事实材料，而不是替用户草率定性？
- 微信小程序、本地单机 App 和律师服务入口，分别应该承担什么角色？

## 重要说明

本项目当前仅为产品交互原型，不提供法律服务，页面中的分类、提示、文书和普法内容不构成针对任何具体事项的法律意见。涉及真实争议时，应结合原始材料和完整事实向具备相应资格的专业人士咨询。

本仓库目前尚未指定开源许可证。代码公开用于产品交流和测试反馈，不当然表示授权复制、发布或商业使用。
