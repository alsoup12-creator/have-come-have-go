# Give & Take

> 中文名：**来而有往**
> 当前状态：🚧 早期交互原型，持续开发中

**你的每一份付出，都值得被尊重。**

“来而有往”不是共同账本，也不鼓励人在关系里斤斤计较。它是一款面向个人的关系付出记录与提醒工具：只记录用户自己的付出，在额度、次数或持续月份达到用户设置的提醒线时，以克制的第三方声音呈现事实。

它将作为独立小程序发展，不隶属于、也不导向任何固定律所或律师。用户需要专业意见时，可以自行选择记录范围并主动转发给自己信任的律师。

这个项目来自一名中国律师对真实关系纠纷的观察：很多人在关系中不断付出，却很少停下来看看金额、次数和持续时间。等到关系变化，事实往往已经被情绪和时间冲淡。

我们想尝试做一件更温和的事：

> 记录事实，提示越线，让用户自己看见、自己决定。

## 它关心的不是“钱花到哪里”

普通记账工具通常回答：

> 这笔钱属于餐饮、旅行、购物还是转账？

“来而有往”额外呈现：

> 这笔支出发生在哪段关系？累计金额、付款次数或持续月份，是否已经达到我自己设置的提醒线？

产品不逼问用户，不要求用户给关系或款项下定义，也不根据单方记录自动得出结论。提醒只负责让已经记录的事实和模式被看见；如何理解、是否行动，始终由用户决定。

## 当前可以体验的功能

### 1. 个人关系记录

- 新建并切换朋友、约会、相亲、暧昧、恋人、夫妻等关系；
- “今天”和“记录”始终聚焦当前选中的一段关系，通过顶部关系条切换；
- “说清”始终只针对当前一段关系，不提供跨关系总览或批量处理；
- “我的”使用柱状图比较全部关系；进入单段关系后，可查看累计年度比较或某一年的逐月统计；
- 关系管理入口只放在“我的”；从管理列表选择关系后仍停留在“我的”查看统计，不改变“今天”的当前关系；删除关系前会先提醒用户确认是否已经说清、处理完毕并得到回应，再明确显示将一并删除的本地记录和截图数量；
- 使用文字、截图、拍摄小票或礼物记录金额、时间、类目、转账附言和自己的一句话；
- 截图和小票只处理用户主动选择的图片，并在本地压缩保存；
- 每笔新记录都代表用户自己的支出，不再建立“对方付款”流水；
- 新增记录时必须明确选择所属关系，每段关系独立统计。

### 2. 关系支出觉察

- 查看本月由自己承担的金额；
- 只在达到用户自设提醒线时出现提醒，不评价用户的选择；
- 由用户自行设置月度累计、年度累计、单笔大额、连续付款次数和连续付款月份提醒线；填写 0 可以关闭对应提醒；
- 月度和年度提醒呈现累计额度，次数和月份提醒呈现持续模式；
- 单笔支出达到提醒线后，提供可选的“说清”入口。

### 3. “理想回应”视角

用户在选中一段具体关系后，可以在“我的记录”和“理想回应”之间切换。金额、统计和提醒保持不变，只在金额上方呈现一种符合关系背景的中立回应参照。

这个视角不推断现实中的对方真正怎么想，也不评价关系。它只是从中立视角呈现：一个认真看见这份付出的人，通常可能怎样回应。

> “今天是你付的钱。我会记得这份照顾，也愿意在下一次回应。”

不同关系只影响回应语气，不改变事实，也不生成关于对方心理的结论。它提供的是参照，不是判断。

### 4. 该说清的钱

- 只展示当前关系中达到单笔提醒线的支出，并按月份和类目整理；
- 支持逐笔选择、按筛选范围全选和清空；
- 处理方式先于材料完整度展示：先决定是和对方说清还是请律师看看，再核对截图、附言和上下文材料；
- 提醒检查付款截图、转账附言、前后对话、通话录音、短信、邮件、借条和后续还款；
- “和对方说清”只生成所选记录和沟通文字，不附带截图、照片、私人备注或律师材料；
- “请律师看看”将每笔所选记录与对应截图、照片分别归组，再统一编排为合并 PDF 预览；正式版只向用户选择的律师提供该 PDF 的查看或下载链接；
- 当前网页原型不绑定或推荐任何律师，也不生成真实 PDF、外部链接或微信转发；
- 清楚区分单方记录、对方确认、可靠电子签署和律师意见。

### 5. 法律小课

- 首发内置借款、赠与、电子证据、婚姻财产、夫妻债务、同居财产和彩礼等中国法基础内容；
- 链接至国家法律法规数据库、最高人民法院或最高人民法院公报等官方原文；
- 只做一般普法，不根据用户的单方记录自动认定款项性质；
- 英文界面用于涉及中国的跨国婚姻或涉外关系，法律内容仍以中国法为主。
- 发布者可以通过独立的 `legal-content.js` 增补或更新条目，无需修改页面渲染逻辑。

### 6. 本地隐私机制

- 当前原型不连接业务服务器；
- 没有账户同步、微信钱包读取、自动共享或后台上传；
- 隐私中心会显示本地关系、记录、截图数量和大致空间占用；
- 用户可以主动导出完整本地备份，或清除全部个人数据；
- 达到提醒金额不会自动联系律师，也不会发送任何记录。
- 当前网页原型中的微信转发只展示交互预览，不创建真实链接，也不发送数据。
- 正式版若要让另一台设备打开所选材料，需要在用户逐项确认后临时上传所选副本，并提供随机链接、有效期、撤回和删除能力；未选择的记录仍留在本地。

更完整的产品边界见 [隐私机制草案](./隐私机制草案.md)。

## 为什么不做微信付款流水同步

产品不会读取或同步用户的完整微信支付流水。多数个人消费与当前关系无关，整批导入会迫使产品长期清洗、筛选和推测交易用途，也会扩大不必要的数据处理范围。这与“用户主动留下重要事实”的定位不一致。

当前只保留四种主动记录方式：

- 文字记录；
- 付款或聊天截图；
- 拍摄或选择小票；
- 备注礼物名称和金额。

## 聊天材料怎么保存

微信小程序可以调用 [`wx.chooseMessageFile`](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.chooseMessageFile.html)，让用户主动从客户端会话中选择图片或文件，并可一次选择多项。但这只是选择会话里已有的图片或文件，不是读取微信聊天历史；普通文字消息不能直接批量导入成结构化对话。

因此，初期更适合采用截图或长截图。正式小程序可以进一步支持多张聊天截图连续选择、手动排序和完整预览，但不应宣称“导入聊天记录”，也不应在用户不知情时读取聊天内容。保留材料时，尽量保存带有前后文、时间和双方身份线索的完整截图，避免只截取孤立的一句话。

## 提醒功能说明

当前可以体验应用内提醒和浏览器通知。浏览器通知需要用户主动授权，页面关闭后不保证后台送达。

正式小程序若接入微信订阅消息，必须再次取得用户订阅，并遵守平台模板和发送场景限制。提醒服务不应读取或保存用户的完整关系记录。

## 目前还没有实现

- 聊天截图多选、顺序整理及长图预览；
- OCR 自动识别并核验付款信息；
- 服务器、账户及跨设备同步；
- 正式微信订阅消息提醒；
- 双方身份核验和可靠电子签署；
- 可撤销、会过期的临时分享服务；
- 可作为正式证据保险箱的加密、可信时间戳和完整性验证。

## 在 Windows 上体验

无需安装依赖：

1. 下载或克隆本仓库；
2. 双击 `启动体验.cmd`；
3. 浏览器会自动打开原型。

也可以直接打开 `index.html`。建议使用 Edge 或 Chrome。

当前数据保存在打开页面的浏览器中。测试前请记住：清理浏览器数据可能导致记录消失，不要将本原型作为重要材料的唯一备份。

### 法律小课内容更新

发布者如需新增或更新法律小课，只需编辑 `legal-content.js`：

- 新增唯一 `id` 的条目，即可追加内容；
- 使用与内置条目相同的 `id`，即可更新对应内容；
- 每条内容应包含中英文标题、摘要、依据和官方链接；
- 正式发布前，应重新核对现行文本、施行状态及官方来源；
- 该文件只保存公共普法内容，不得写入用户资料、个案事实或咨询意见。

## 接下来想探索什么

项目仍处于非常早期的产品验证阶段，目前更关心问题是否真实，而不是快速堆叠功能：

- 人们是否愿意记录较大或长期单方面的关系支出？
- 怎样提醒，既能让人看见自己，又不制造对立和焦虑？
- 哪些款项值得邀请对方确认？
- 如何在“完全本地保存”和“双方协作确认”之间建立清楚边界？
- 怎样生成一份对 AI 和律师都真正有用的事实材料，而不是替用户草率定性？
- 微信小程序如何在默认本地保存与用户主动跨设备分享之间保持清楚边界？

本项目当前仅为产品交互原型，不提供法律服务，页面中的分类、提示、文书和普法内容不构成针对任何具体事项的法律意见。涉及真实争议时，应结合原始材料和完整事实向具备相应资格的专业人士咨询。
